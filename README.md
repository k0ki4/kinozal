# Наш кинозал

Закрытый сайт для синхронного просмотра видео вдвоём: общий плеер, чатик, реакции, очередь и «кто онлайн».

**Что можно смотреть**

| Режим | Как работает | Что нужно |
|---|---|---|
| YouTube · обычный плеер | Встроенный плеер YouTube, видео грузится напрямую с YouTube | В России — включённый VPN у обоих |
| YouTube · через сервер | Сервер сам скачивает ролик (yt-dlp) и отдаёт вам со своего адреса | Свой VPS. VPN не нужен |
| Ссылка · прямо в браузере | Прямая ссылка на видеофайл или поток (.mp4, .webm, .m3u8). Каждый браузер грузит видео сам | Ссылка должна открываться у обоих |
| Ссылка · через сервер | Ссылка на страницу любого сайта, который умеет yt-dlp (VK Видео, Rutube и сотни других). Сервер достаёт видео и отдаёт вам | Свой VPS |
| Файл · загрузить на сервер | Загружаешь файл один раз, оба смотрите с сервера | Место на сервере (лучше VPS) |
| Файл · у каждого свой | У обоих лежит одинаковый файл, синхронизируется только управление | Ничего, работает везде |

Режимы «через сервер» включаются настройкой `YTDLP=on`. Если она выключена, эти кнопки на сайте просто неактивны.

**Про ссылки с других сайтов.** Синхронизировать можно только видео, которое играет в нашем плеере. Если на сайте фильм крутится в его собственном плеере, остаётся два пути: найти прямую ссылку на видеофайл или поток, либо вставить ссылку на страницу в режиме «через сервер» (сработает, если yt-dlp поддерживает этот сайт). Видео с защитой DRM (стриминговые сервисы по подписке) не открыть никак. У многих сайтов прямые ссылки временные или привязаны к адресу того, кто их получил, поэтому у второго человека такая ссылка может не открыться — тогда выручает режим «через сервер».

---

## Как сайт защищён от чужих

- Регистрации нет. Аккаунты (твой и котя) прописаны в настройках сервера, пароли хранятся только в виде хэша.
- Без входа открывается только страница с паролем. Плеер, чат, очередь, видеофайлы и канал синхронизации без входа не отдаются.
- После 5 неверных паролей с одного адреса вход для него закрывается на 15 минут. Если неверных попыток очень много со всех адресов сразу — вход закрывается для всех на 15 минут.
- Вход запоминается на 30 дней (настраивается). Если сменить пароль в настройках — все старые входы перестанут работать.
- Сайт просит поисковики его не индексировать, запрещает встраивать себя на чужие страницы и не пускает подключения с чужих сайтов.
- На хостинге обязательно используй https (на Render он есть сразу, на VPS его даёт Caddy).

**Пароли бери длинные** — 14+ символов, лучше несколько случайных слов. Это главное, на чём держится защита.

## 1. Попробовать у себя на компьютере

Нужен [Node.js](https://nodejs.org) версии 18.17 или новее.

```bash
npm install
cp .env.example .env
npm run secret                       # скопируй результат в SESSION_SECRET
npm run hash -- "пароль-для-меня"     # результат → USER_1=me:...
npm run hash -- "пароль-для-котя"     # результат → USER_2=kot:...
npm start
```

Открой http://localhost:3000 и войди. Чтобы проверить синхронизацию, открой сайт во втором браузере (или в окне инкогнито) и войди вторым аккаунтом.

## 2. Вариант А — бесплатный хостинг (Render)

Подходит для режимов **YouTube · обычный плеер (с VPN)** и **Файл · у каждого свой**.

1. Залей папку проекта в **приватный** репозиторий на GitHub (файл `.env` туда не попадёт — он в `.gitignore`).
2. На render.com: **New → Web Service**, выбери репозиторий.
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Тариф: Free
3. Во вкладке **Environment** добавь переменные:
   - `SESSION_SECRET` — из `npm run secret`
   - `USER_1`, `USER_1_NAME`, `USER_2`, `USER_2_NAME` — как в `.env`
   - `UPLOADS=off`
   - `YTDLP=off`
4. Готово — Render даст адрес вида `https://что-то.onrender.com`, уже с https.

Особенности бесплатного тарифа: после ~15 минут без посетителей сервер засыпает, и первое открытие занимает около минуты. При перезапуске чат и очередь стираются (диск временный).

## 3. Вариант Б — свой VPS (всё, включая YouTube через сервер)

Подойдёт самый маленький сервер за границей (1 ядро, 1–2 ГБ памяти, 20+ ГБ диска) с Ubuntu 24.04. Ещё нужен домен для https — подойдёт бесплатный поддомен, например на duckdns.org: заведи его и направь на IP сервера.

### Установка

Подключись к серверу по SSH и выполни:

```bash
# Node.js, ffmpeg (склеивает видео и звук), Caddy (https)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs ffmpeg unzip caddy

# yt-dlp — официальная сборка
sudo curl -L https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp_linux -o /usr/local/bin/yt-dlp
sudo chmod a+rx /usr/local/bin/yt-dlp

# Deno — с конца 2025 года yt-dlp нужен JavaScript-движок для YouTube
curl -fsSL https://deno.land/install.sh | sudo DENO_INSTALL=/usr/local sh -s -- -y
```

Если с Deno что-то не так, можно обойтись Node: в `.env` поставь `YTDLP_JS_RUNTIME=node`.

### Сам сайт

```bash
sudo useradd -r -m -d /opt/kinozal kinozal
# скопируй файлы проекта в /opt/kinozal (через git clone или scp), затем:
cd /opt/kinozal
sudo -u kinozal npm install --omit=dev
sudo -u kinozal cp .env.example .env
sudo -u kinozal nano .env
```

В `.env` заполни `SESSION_SECRET`, `USER_1`, `USER_2`, а также:

```
PORT=3000
UPLOADS=on
YTDLP=on
YTDLP_BIN=/usr/local/bin/yt-dlp
```

Запуск как службы (сам поднимется после перезагрузки):

```bash
sudo cp deploy/kinozal.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now kinozal
sudo systemctl status kinozal      # должно быть active (running)
```

Https через Caddy — впиши свой домен в `deploy/Caddyfile` и:

```bash
sudo cp deploy/Caddyfile /etc/caddy/Caddyfile
sudo systemctl reload caddy
sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable
```

Через минуту сайт откроется по `https://твой-домен`.

### Проверить yt-dlp

```bash
sudo -u kinozal yt-dlp -F "https://www.youtube.com/watch?v=jNQXAC9IVRw"
```

Если видишь список форматов — всё работает. Если пишет **«Sign in to confirm you're not a bot»** — YouTube не доверяет адресу сервера. Тогда:

- **прокси**: купи резидентный прокси и впиши его в `.env`: `YTDLP_PROXY=http://логин:пароль@адрес:порт`;
- или **cookies**: выгрузи cookies YouTube из браузера (формат Netscape, есть расширения «Get cookies.txt»), положи файл на сервер и укажи `YTDLP_COOKIES=/opt/kinozal/cookies.txt`. Лучше использовать запасной аккаунт Google, а не основной.

После изменения `.env`: `sudo systemctl restart kinozal`.

YouTube часто что-то меняет, поэтому yt-dlp стоит обновлять: `sudo yt-dlp -U` (можно раз в неделю).

Скачанные ролики хранятся в `data/yt`. Когда кэш больше `CACHE_MAX_GB`, старые удаляются сами. Ролик, который сейчас включён, и ролики из очереди не трогаются.

> Скачивание роликов формально нарушает правила YouTube. Для личного просмотра вдвоём это обычно никого не волнует, но имей в виду.

## Шестерёнка «Настройки видео»

Справа на панели управления. У каждого свои настройки, второму они не передаются.

- **YouTube (обычный плеер):** субтитры (по умолчанию выключены) и «Показать меню YouTube». Этот пункт открывает родные кнопки YouTube: там звуковая дорожка и качество. Плей, пауза и перемотка через эти кнопки тоже общие. Скорость там лучше не менять — собьётся синхронизация.
- **Ссылки .m3u8:** качество, звуковая дорожка (озвучка) и субтитры, если их отдаёт сайт.
- **Через сервер:** скачивается одна звуковая дорожка. Какую — задаёт `YTDLP_AUDIO_LANG` в настройках (например, `ru`). Если такой нет, берётся оригинальная.

## Настройки (.env)

| Переменная | Что это |
|---|---|
| `SESSION_SECRET` | Длинная случайная строка, `npm run secret` |
| `USER_1`, `USER_2` | `логин:хэш`, хэш — `npm run hash -- "пароль"` |
| `USER_1_NAME`, `USER_2_NAME` | Как показывать имя на сайте |
| `SESSION_DAYS` | Сколько дней помнить вход (30) |
| `DATA_DIR` | Где хранить чат, очередь, файлы (`./data`) |
| `UPLOADS` | `on`/`off` — загрузка файлов на сервер |
| `MAX_UPLOAD_MB` | Максимальный размер файла (4096) |
| `YTDLP` | `on`/`off` — режим «YouTube через сервер» |
| `YTDLP_BIN` | Путь к yt-dlp |
| `YTDLP_PROXY` | Прокси для yt-dlp |
| `YTDLP_COOKIES` | Файл cookies YouTube |
| `YTDLP_JS_RUNTIME` | `node`, если не ставил Deno |
| `YTDLP_FORMAT` | Качество для YouTube (по умолчанию до 1080p) |
| `YTDLP_FORMAT_OTHER` | Качество для остальных сайтов (по умолчанию до 1080p) |
| `YTDLP_AUDIO_LANG` | Какую звуковую дорожку качать «через сервер», если их несколько: `ru`, `en`, `ja`… Пусто — оригинальную |
| `CACHE_MAX_GB` | Сколько места под скачанное (20) |

## Если что-то не так

- **YouTube в обычном режиме не грузится** — включите VPN у обоих и обновите страницу, или используйте режим «через сервер».
- **«Автор запретил показ на других сайтах»** — некоторые ролики нельзя встраивать. Режим «через сервер» их покажет.
- **Файл не открывается** — браузеры уверенно играют mp4 (H.264 + AAC) и webm. Некоторые .mkv не пойдут — переконвертируй в mp4.
- **Видео не стартует само после открытия страницы** — браузер требует одно нажатие, чтобы включить звук. Нажми большую кнопку на плеере.
- **Сброс чата/очереди** — останови сервер и удали `data/state.json`.
- **Логи на VPS** — `sudo journalctl -u kinozal -f`.
